Installer et héberger ton bot.

Le site vitrine est statique; le worker WhatsApp doit tourner séparément sur un environnement persistant.

Sur cette pagePrérequisInstallationConfigurationDémarrerService détachéHébergement cloudRègles d’or

Prérequis

  • Node.js ≥ 22.22 (exigé par @distube/ytdl-core et Baileys) ; vérifie avec node -v.
  • Un numéro WhatsApp secondaire est fortement conseillé.
  • ffmpeg est fourni via ffmpeg-static; rien à installer à l’extérieur.
  • Docker est facultatif, uniquement pour l’hébergement en conteneur.

Cloner et installer

git clone https://github.com/Beaute-Gar/DJOUSSE-TECH-MD.git
cd DJOUSSE-TECH-MD
npm install

Configurer l’instance

Copie .env.example vers .env à la racine, puis remplis au minimum l’identité et le propriétaire. Le modèle complet et commenté reste .env.example : ne devine pas les noms de variables.

# ── Identité ─────────────────────────────────────
BOT_NAME=DJOUSSE TECH MD
PREFIX=.
OWNER_NUMBER=237XXXXXXXXX
OWNER_NAME=DJOUSSE TECH

# ── Sessions et sauvegarde ───────────────────────
# Clé de sauvegarde chiffrée des sessions (recommandé)
SESSION_BACKUP_KEY=

# ── Démarrage et anti-ban ────────────────────────
AUTO_START=true
HUMANIZE=true
HUMANIZE_PER_MINUTE=18

# ── IA (facultatif) ──────────────────────────────
# Ordre essayé : Anthropic → Gemini → Groq → OpenRouter
# puis Pollinations (gratuit, sans clé). AV_AI=off coupe l’IA.
ANTHROPIC_API_KEY=
GEMINI_KEY=
GROQ_API_KEY=
OPENROUTER_API_KEY=
AV_AI=on

# ── Statuts automatiques ─────────────────────────
# AUTO_STATUS=off pour ne rien publier
AUTO_STATUS=on
STATUS_LIKE=true
STATUS_LIKE_EMOJI=❤️

# ── Jeux, pronostics, mode nuit ──────────────────
GAMES_AI=on
PROMO_TZ=Africa/Douala
NIGHT_TZ=Africa/Douala

# ── Protections (valeurs par défaut) ─────────────
BADWORDS_LIGHT=true
BADWORDS_KICK=

Toutes les clés sont facultatives sauf l’identité. Sans clé IA, les commandes concernées renvoient un message explicite. Les protections se règlent ensuite par commande dans chaque groupe (.antilink on, .welcome on…). Le fichier .env n’est jamais commité et ne doit jamais être publié.

Démarrer

npm start

La console demande un numéro : saisis-le au format international sans + (ex. 237690000000). Le bot affiche ensuite un code d’appairage à 8 caractères. Dans WhatsApp : Appareils connectés → Connecter un appareil → Associer avec un numéro de téléphone. Les identifiants sont écrits dans storage/sessions/, ignoré par git.

Les commandes liste et quitter restent disponibles dans la console. Aux démarrages suivants, les sessions enregistrées se reconnectent seules tant que AUTO_START=true.

Service détaché (PM2)

ecosystem.config.cjs décrit le processus dte-bot (redémarrage automatique, limite mémoire). PM2 le maintient actif après la fermeture du terminal.

npm install -g pm2
pm2 start ecosystem.config.cjs
pm2 status
pm2 logs dte-bot
pm2 save

Le bot tient aussi son propre journal quotidien dans storage/logs/ (un fichier par date, conservé 14 jours). Suivi en direct sous Windows : Get-Content storage\logs\*.log -Tail 20 -Wait.

Sous Linux, pm2 startup puis pm2 save relancent le service après un redémarrage. Sous Windows, le plus simple est une tâche du Planificateur de tâches au démarrage de session.

Hébergement (machine locale + ngrok ou alternatives)

Le bot/serveur tourne sur votre machine locale (recommandé dans cette configuration) et peut être exposé au site Vercel via un tunnel ngrok (HTTPS). Les fichiers de déploiement alternatifs sont regroupés dans deployment/ ; le contexte de build reste la racine du dépôt.

Vercel héberge le site et les relais /api ; le worker/serveur applicatif tourne sur votre machine (ou une alternative) et doit rester accessible et persistant.

Règles d’or (local & tunnel)

  1. Persistance : conservez tout le dossier storage/ (sessions, base, téléchargements, logs). Sans lui, réappairage et perte de configuration.
  2. Code d’appairage : affiché dans la console interactive du bot. Pour un service sans console, appairez en local puis copiez storage/sessions/.
  3. Une seule instance : un seul déploiement actif par numéro WhatsApp.
  4. Secrets & exposition : .env reste sur l’hôte (jamais dans Git/site) ; le backend écoute en local (127.0.0.1) et n’est exposé que via le tunnel ngrok configuré.
ImportantLe worker Baileys doit être exécuté dans un environnement persistant. Les fonctions serverless de Vercel servent au site et au relais sécurisé du jumelage, pas au worker WhatsApp.
