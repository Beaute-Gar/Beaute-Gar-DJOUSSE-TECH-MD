## ✨ Présentation

**DJOUSSE TECH MD** est un bot WhatsApp **multi-device** basé sur [Baileys](https://github.com/WhiskeySockets/Baileys), conçu pour la modération de groupe, les protections, les médias, les téléchargements, les outils et l’IA — avec une expérience **100 % texte** pilotée par un **menu à chiffres**.

- 🧠 **Navigation simple** : un menu lisible, des catégories, des commandes accessibles au clavier/chiffres.
- 🛡️ **Protections de groupe (DJOUSSE GUARD)** : moteur de protections configurable pour sécuriser les groupes.
- 🤖 **IA & médias** : commandes IA, stickers/médias, conversions et téléchargements (selon configuration).
- ⚙️ **Architecture modulaire** : handlers, librairies, commandes, jeux et composants web séparés.

> ⚠️ **Projet indépendant**, non affilié à WhatsApp ni à Meta. L’utilisation de bibliothèques non officielles peut comporter des risques (restrictions/suspension de compte). Utilisez le bot de manière responsable.

## 🚀 Fonctionnalités principales

- **Menu & commandes texte** : navigation par chiffres, catalogue de commandes et catégories.
- **Modération & groupe** : outils d’administration de groupe (selon droits/permissions WhatsApp).
- **Protections** : anti-lien, anti-spam/flood, anti-médias/mentions, etc. (DJOUSSE GUARD).
- **Médias** : stickers, conversions, récupération de médias (ex. vue unique si disponible).
- **Téléchargements & recherche** : outils média/recherche (selon disponibilité des services).
- **IA** : commandes IA (selon clés/services configurés).
- **Pronostics football** : `.promo` (ticket du jour), `.promo list`, `.promo live`, `.promo ticket [n] [mise]`, `.promo ticket safe` — ticket clair avec probabilité, cote totale, gain potentiel et niveau de risque (TipsAudit + SportMonks/Infersports).
- **Multi-session / ownership** : prise en charge des sessions connectées et du routage des actions selon le contexte (groupe/session).

## ⚙️ Configuration

Créez un fichier `.env` à partir de [`.env.example`](./.env.example) et adaptez les valeurs à votre environnement.

Exemples de variables courantes (voir `.env.example` pour la liste complète) :

```env
BOT_NAME=DJOUSSE TECH MD
PREFIX=.
OWNER_NUMBER=
OWNER_NAME=DJOUSSE TECH

# Clés/services optionnels (IA, médias, recherche, etc.)
ANTHROPIC_API_KEY=
GEMINI_KEY=
GROQ_API_KEY=
OPENROUTER_API_KEY=
```

### API de jumelage / statut (pairing)

Le bot peut exposer une API locale (selon configuration dans `index.js` / variables d’environnement) pour le jumelage et le statut, notamment :

- `GET /health`
- `GET /status`
- `POST /pair` (avec en-tête `x-api-token` si `PAIRING_API_TOKEN` est défini)

Variables typiques :

```env
PAIRING_API_TOKEN=
PAIRING_HOST=127.0.0.1
PAIRING_PORT=3001
# PORT=3001
```

> Exposez l’API uniquement via un canal sécurisé (ex. tunnel HTTPS, reverse proxy, restrictions d’accès). N’ouvrez pas de services sensibles publiquement sans protection.

## 🌐 Site web & jumelage (Vercel + backend local)

Le dossier [`web/`](./web) contient le site statique et les fonctions/proxies d’API (Vercel) utilisés notamment pour le jumelage.

- **Site (production)** : https://beaute-gar-djousse-tech-md-web.vercel.app/
- **Pages utiles** : [Accueil](https://beaute-gar-djousse-tech-md-web.vercel.app/), [Commandes](https://beaute-gar-djousse-tech-md-web.vercel.app/commandes.html), [Connexion](https://beaute-gar-djousse-tech-md-web.vercel.app/connexion.html), [Installation](https://beaute-gar-djousse-tech-md-web.vercel.app/installation.html)

### Architecture de jumelage (exemple de déploiement)

- **Front (Vercel)** : sert le site et relaie les appels (`web/api/*`) vers l’API du bot.
- **Backend/bot (local)** : tourne sur la machine hôte (ex. `127.0.0.1:3001`) et expose `/status`, `/health`, `/pair`.
- **Tunnel HTTPS (ex. ngrok)** : expose l’API locale au front Vercel de façon sécurisée.

Variables côté Vercel (exemples) :

```env
PAIRING_API_URL=https://<votre-tunnel-ngrok>
PAIRING_API_TOKEN=<jeton-partage>
SITE_ORIGIN=https://beaute-gar-djousse-tech-md-web.vercel.app
```

> Le token doit correspondre côté bot et côté Vercel. Vérifiez aussi CORS/origine et les protections d’accès avant toute mise en production.

├─ src/
